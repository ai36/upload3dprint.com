# upload3dprint.com — инструкции для агентов

Проект ведётся по spec-driven development. Перед любой работой прочитай `README.md`, `constitution.md` и текущую спецификацию в `specs/`.

- Не пиши код, пока спецификация не утверждена человеком, то есть пока раздел «Уточнения» не закрыт и статус не «утверждена».
- Меняется поведение — сначала правь спецификацию, потом код.
- Порядок артефактов: spec.md → plan.md → tasks.md → код. Каждый следующий ссылается на пункты предыдущего (FR-xxx, SC-xxx).
- Не выдумывай факты о человеке и бизнесе: всё неизвестное помечай `[NEEDS CLARIFICATION]`.
- Сайт на английском, документация проекта на русском.
- Никаких новых зависимостей без записи в `plan.md` и решения человека. Минимальный код, сначала переиспользуй то, что уже есть.
- Пиши кратко и по делу.
- Git: вся разработка в ветке `dev`. В `main` попадает только слиянием из `dev` по решению человека. После каждого этапа fullstack главный агент делает commit и push в `dev`. Репозиторий: `git@github.com:ai36/upload3dprint.com.git`.

## Роли
- **Главный агент** ведёт spec.md, plan.md, tasks.md, документацию и журнал `docs/log.md`. Код не пишет.
- **Субагент `fullstack`** (`.claude/agents/fullstack.md`) пишет код только по утверждённой спецификации и tasks.md.
- **Наблюдатель** `bash .claude/scripts/spec-watch.sh watch` раз в минуту проверяет утверждённые спецификации (статус «утверждена»). Изменения в черновиках он не видит. Запускается при старте сессии через хук SessionStart.

- Связанная система управления целями — `D:\_myWork\newlive` (гипотеза H17).
